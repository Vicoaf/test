# PROXTEL Documentation Standard v1.0

Documentation must be source-grounded, audience-specific, maintainable and explicit about assumptions.

Domain-specific facts come from the owning area or direct evidence. Examples must be clearly distinguished from current system behavior.

Operational procedures require prerequisites, expected outcomes, failure/rollback guidance where appropriate, and no exposed secrets.

Runbooks and release notes must preserve traceability to the change or evidence they describe.

Repository tooling changes are delegated to Development. Commit, push and deployment remain explicitly authorized actions.
